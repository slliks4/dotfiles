# Optional Tree-sitter Setup

Tree-sitter provides more accurate syntax highlighting by parsing the structure
of source code.

It is not required by this configuration. Neovim's built-in syntax
highlighting remains the default.

## Requirements

A manual Tree-sitter installation generally requires:

* Neovim 0.9 or newer
* A C compiler
* `make` or the build system required by the grammar
* The grammar for each desired language
* Matching Tree-sitter query files
* Optionally, the Tree-sitter CLI

Parser and query compatibility depends on the versions of Neovim, Tree-sitter,
the language grammar, and the queries being used.

Older Neovim releases may not load parsers generated by current versions of
Tree-sitter. Likewise, newer queries may reference grammar nodes or Neovim
features that older versions do not support.

## Runtime directories

On a standard Unix installation, create the parser and query directories:

```sh
mkdir -p ~/.config/nvim/parser
mkdir -p ~/.config/nvim/queries
```

The resulting structure for TypeScript and TSX will look similar to:

```text
~/.config/nvim/
├── parser/
│   ├── typescript.so
│   └── tsx.so
└── queries/
    ├── javascript/
    │   └── highlights.scm
    ├── jsx/
    │   └── highlights.scm
    ├── typescript/
    │   └── highlights.scm
    └── tsx/
        └── highlights.scm
```

Neovim searches for parsers and queries inside directories found on its
`runtimepath`.

The shared-library extension may differ by platform:

* Linux and similar systems generally use `.so`
* macOS may use `.dylib`
* Windows may use `.dll`

## Obtaining a parser

Language grammars can be found through the Tree-sitter GitHub organization.

For TypeScript and TSX:

[https://github.com/tree-sitter/tree-sitter-typescript](https://github.com/tree-sitter/tree-sitter-typescript)

Clone and build the grammar:

```sh
git clone https://github.com/tree-sitter/tree-sitter-typescript
cd tree-sitter-typescript
make
```

The repository contains separate TypeScript and TSX grammars. Its top-level
Makefile builds both.

Locate the generated shared libraries:

```sh
find typescript tsx -type f \
    \( -name "*.so" -o -name "*.dylib" -o -name "*.dll" \)
```

Copy the libraries into Neovim's parser directory and name them after their
Tree-sitter languages.

For Linux, the result should be:

```text
~/.config/nvim/parser/typescript.so
~/.config/nvim/parser/tsx.so
```

For example:

```sh
cp /path/to/typescript-library.so \
    ~/.config/nvim/parser/typescript.so

cp /path/to/tsx-library.so \
    ~/.config/nvim/parser/tsx.so
```

The exact output names and locations may differ between grammar repositories.
Inspect the grammar's build instructions before copying the parser.

Parsers should normally be compiled on the machine where they will be used.
Committing precompiled shared libraries can cause compatibility problems across
operating systems, processor architectures, and C libraries.

## Obtaining queries

Highlight queries can be obtained from the `nvim-treesitter` repository:

[https://github.com/nvim-treesitter/nvim-treesitter/tree/main/runtime/queries](https://github.com/nvim-treesitter/nvim-treesitter/tree/main/runtime/queries)

Copy only the query directories needed by the installed languages.

For TypeScript and TSX, copy:

```text
runtime/queries/javascript
runtime/queries/jsx
runtime/queries/typescript
runtime/queries/tsx
```

Older repository revisions may place these directories under `queries/`
instead of `runtime/queries/`.

The additional JavaScript and JSX query directories may be required because
TypeScript and TSX queries can inherit from them.

Query inheritance is declared near the beginning of a query file:

```scheme
; inherits: javascript
```

or:

```scheme
; inherits: typescript,jsx
```

The queries must match the parser grammar. Pinning the grammar and queries to
known-compatible Git revisions is safer than always copying their latest
versions.

The current `nvim-treesitter` branch may also require a newer Neovim version
than this configuration. Do not assume that its latest queries will work with
Neovim 0.9.

## Configuration

Create:

```text
lua/slliks4/core/treesitter.lua
```

Add:

```lua
if vim.fn.has("nvim-0.9") == 0 then
    return
end

-- Use the TSX parser for React TypeScript files.
vim.treesitter.language.register("tsx", "typescriptreact")

vim.api.nvim_create_autocmd("FileType", {
    group = vim.api.nvim_create_augroup("TreesitterAutoStart", {
        clear = true,
    }),
    pattern = "*",
    callback = function(args)
        local filetype = vim.bo[args.buf].filetype

        -- Resolve registered aliases and defensively fall back to the filetype.
        local lang =
            vim.treesitter.language.get_lang(filetype) or filetype

        local ok, loaded = pcall(
            vim.treesitter.language.add,
            lang
        )

        if not ok or not loaded then
            return
        end

        pcall(vim.treesitter.start, args.buf, lang)
    end,
})
```

Load it from `lua/slliks4/init.lua`:

```lua
require("slliks4.core.treesitter")
```

The `FileType` autocommand runs for every filetype, but Tree-sitter starts only
when a compatible parser can be loaded.

Languages without an installed parser continue using Neovim's built-in syntax
highlighting.

## Adding another language

To add another language:

1. Obtain its Tree-sitter grammar.
2. Compile its parser.
3. Copy the shared library into `~/.config/nvim/parser/`.
4. Copy its matching queries into `~/.config/nvim/queries/`.
5. Restart Neovim and open a file of that type.

No change to `treesitter.lua` is normally required because the configuration
checks for available parsers automatically.

A language mapping is needed only when the Neovim filetype differs from the
Tree-sitter parser name:

```lua
vim.treesitter.language.register("parser_name", "filetype_name")
```

## Checking the installation

Open a file for the installed language and run:

```vim
:InspectTree
```

To inspect the highlight capture under the cursor:

```vim
:Inspect
```

Check the detected filetype:

```vim
:set filetype?
```

Check which Tree-sitter language is associated with it:

```vim
:lua print(vim.treesitter.language.get_lang(vim.bo.filetype))
```

Check whether Neovim can find the TypeScript parser:

```vim
:lua print(vim.inspect(vim.api.nvim_get_runtime_file("parser/typescript.*", true)))
```

Check whether Neovim can find its highlight query:

```vim
:lua print(vim.inspect(vim.api.nvim_get_runtime_file("queries/typescript/highlights.scm", true)))
```

If the parser loads but highlighting fails, the parser and query versions may
not be compatible.

## Using the Tree-sitter CLI

The Tree-sitter CLI can generate parser source code from a language grammar:

```sh
tree-sitter generate
```

This generates source code, usually including `src/parser.c`. It does not
necessarily create the shared library that Neovim loads.

The generated source must still be compiled into a `.so`, `.dylib`, or `.dll`
file.

Many grammar repositories already include generated parser source, so the CLI
is not always required unless the grammar needs to be regenerated.

## Using your system package manager

Some system package managers provide the Tree-sitter CLI or precompiled
language parsers.

Package names and installation locations differ between operating systems and
Linux distributions. Consult the package manager's repository to see which
grammars are available.

If a package installs a compatible parser outside Neovim's runtime path, copy
or link its shared library into:

```text
~/.config/nvim/parser/
```

Name the installed library after its Tree-sitter language, such as:

```text
c.so
lua.so
typescript.so
tsx.so
```

Installing the Tree-sitter CLI alone does not install language parsers or
queries automatically.

## Using a plugin instead

A Neovim plugin manager can install `nvim-treesitter`, which can manage parser
and query installation automatically.

This is easier to maintain but introduces a plugin dependency. It is an
alternative to the manual setup described here and is not required by the base
configuration.

Always check the plugin's current Neovim version requirements before installing
it:

[https://github.com/nvim-treesitter/nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter)
